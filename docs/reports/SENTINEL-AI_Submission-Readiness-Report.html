5. The local error: npm run doctor

The only failing preflight check is “Atlas is refusing this machine's IP address.” Node 24, the .env keys, Atlas DNS and all three ports pass. This is not a code defect: MongoDB Atlas only accepts connections from addresses on its Network Access list, and this computer's public IP has changed since it was added (home and mobile connections change IP often).

  1. Atlas → Security → Network Access → Add IP Address → Add Current IP Address. Add a comment such as “Ilyas laptop 17 Oct”.
  2. Wait until the entry shows Active (about a minute), then run npm run doctor and npm run demo again.
  3. Do not add 0.0.0.0/0. Do not remove 34.21.228.185/32 — that is the Cloud NAT address the deployed services use.

The deployed application is unaffected: it reaches Atlas through the Cloud NAT IP, which is why the live URL keeps working.

Step 2 in detail — enabling Gemini on Cloud Run

The model identifiers are configuration, never code (CLAUDE.md, T§7). First check which models the project can call. In Cloud Shell, in project project-f4c013ec-ed17-479b-999:

for m in gemini-2.5-flash gemini-2.5-pro; do echo "== $m"; curl -s -X POST -H "Authorization: Bearer $(gcloud auth print-access-token)" -H "Content-Type: application/json" "https://aiplatform.googleapis.com/v1/projects/project-f4c013ec-ed17-479b-999/locations/global/publishers/google/models/$m:generateContent" -d '{"contents":[{"role":"user","parts":[{"text":"Reply with the word OK"}]}]}' | head -c 400; echo; done

If a model returns 404 or “not found”, open Vertex AI → Model Garden and use the current Gemini Flash / Pro IDs listed there instead. The deep tier has a 15-second ceiling; if the Pro model is slower than that on the demo account, use the Flash model for both tiers.

Then apply the verified IDs to the running service immediately (no rebuild):

gcloud run services update sentinel-core --region asia-southeast1 --update-env-vars VERTEX_LOCATION=global,GEMINI_FAST_MODEL=gemini-2.5-flash,GEMINI_DEEP_MODEL=gemini-2.5-pro

Finally make it permanent so the next push does not reset it: set _GEMINI_FAST_MODEL and _GEMINI_DEEP_MODEL in the Cloud Build trigger's substitutions (or as the defaults in infra/cloud-build/cloudbuild.yaml). The service account sentinel-core already holds roles/aiplatform.user and the Vertex AI API is enabled by the bootstrap script.
